# Contributing

This is a personal portfolio project, but the repository is documented like a professional
software product.

## Development Principles

- Keep changes small and intentional.
- Document major product and architecture decisions.
- Prefer reusable components over one-off UI.
- Preserve accessibility and performance while adding animation.
- Keep project case studies honest and specific.

## Commit Style

Use clear commit messages:

- `docs: add product vision`
- `docs: expand product requirements`
- `feat: add portfolio shell`
- `feat: add skill crystal component`
- `fix: improve mobile navigation`
- `perf: optimize animated scene assets`

## Review Checklist

Before merging or publishing major changes:

- Does the change support the portfolio vision?
- Is the UI responsive?
- Is keyboard navigation preserved?
- Does the content remain readable without animation?
- Are links and CTAs working?
- Is documentation updated if needed?
