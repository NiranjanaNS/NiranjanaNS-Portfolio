# Decision Log

This file records important product and engineering decisions.

## 2026-07-08: Build as a Product, Not a Basic Portfolio

Decision:

Treat the portfolio as a product-quality engineering project with documentation, architecture,
case studies, and success metrics.

Reason:

This better demonstrates readiness for product-based companies than a static portfolio alone.

## 2026-07-08: Use Cinematic Storytelling Carefully

Decision:

Use a horizontal journey and animated world, but keep content clarity and performance as the
highest priorities.

Reason:

The portfolio should be memorable, but recruiters and engineers still need fast access to proof.

## 2026-07-08: Build Design-System First

Decision:

Before coding full scenes, build reusable foundations such as buttons, cards, typography,
navigation, project cards, skill crystals, and timeline items.

Reason:

This keeps the UI consistent and makes later sections faster and easier to maintain.

## 2026-07-08: Avoid Skill Percentage Bars

Decision:

Represent skills with contextual details instead of percentages.

Reason:

Percentages are vague. Project usage, libraries, experience notes, and implementation examples
are more credible.
