# Goals and Success Metrics

## Primary Goal

Build a product-quality portfolio that helps Niranjana stand out for product-based software
engineering roles by proving both frontend craft and engineering maturity.

## User Goals

### Recruiter

- Understand Niranjana's role, skills, and strongest projects quickly.
- Access resume, GitHub, LinkedIn, and email without friction.
- See enough proof to continue the conversation.

### Hiring Manager

- Evaluate project ownership and technical depth.
- Understand how Niranjana approaches problems and tradeoffs.
- See evidence of production-minded engineering.

### Technical Interviewer

- Review architecture, implementation choices, and lessons learned.
- Inspect GitHub repositories and live demos.
- Find useful discussion points for interviews.

## Product Goals

- Create a memorable first impression.
- Keep navigation clear and predictable.
- Make projects the strongest part of the portfolio.
- Document engineering decisions openly.
- Build reusable components and maintainable code.
- Keep performance and accessibility high despite animation.

## Success Metrics

### Experience

- Visitor understands the portfolio's purpose within 10 seconds.
- Recruiter can find resume and contact links within 30 seconds.
- Project case studies are easy to scan and explore.
- Mobile users can access all content without hover-only interactions.

### Engineering

- Lighthouse Performance: 95+ target.
- Lighthouse Accessibility: 95+ target.
- Lighthouse Best Practices: 100 target.
- Lighthouse SEO: 95+ target.
- No critical console errors in production.
- No layout-breaking text overflow on mobile.

### Content

- At least three flagship projects documented with case studies.
- Each flagship project includes problem, solution, architecture, stack, decisions, links, lessons,
  and future improvements.
- Engineering Hub includes architecture, folder structure, testing, deployment, and performance
  strategy.

### Repository Quality

- README explains the product clearly.
- Docs folder shows planning and architecture.
- Commit history reflects meaningful progress.
- Code is organized by shared UI and feature sections.

## Constraints

- Keep animation purposeful.
- Keep content accessible without sound.
- Keep the first release realistic.
- Avoid adding tools only because they are trendy.
- Prefer maintainability over visual tricks.
